## 논의할 내용

### 1. 모임 일정과 방식

- 정해진 사항: 주 1회 퇴근 후 모입니다.
- 무슨 요일과 시간에 모일까요?
- 온라인과 오프라인 중 어떤 방식으로 진행할까요?
- 참석이 어렵거나 일정 변경이 필요할 때 어떻게 공유할까요?

### 2. 주제와 프로젝트 범위

- 정해진 사항: 같은 주제를 각자 구현해 모임에서 발표합니다.

- 주제는 어떻게 제안하고 선택할까요?
- 하나의 주제에 얼마 동안 도전할까요?
- 모두에게 공통으로 요구할 기능과 각자 자유롭게 정할 부분은 무엇일까요?
- 완성하지 못했을 때는 어떻게 진행할까요?

### 3. 기술과 개발 환경

- 정해진 사항: 모든 프로젝트에 Python을 사용하고, 버전은 3.13으로 통일합니다.
- 프레임워크와 라이브러리는 각자 자유롭게 선택할까요?

### 4. AI와 참고 자료

- 정해진 사항: 코드 작성과 문제 해결에 AI 도움 없이 직접 진행합니다.
- 공식 문서, 검색, 예제 코드 등은 어떻게 활용할까요?
- 참고한 자료는 어떻게 기록하고 공유할까요?

### 5. 레포지토리와 작업 공유

- 정해진 사항: 주제별 레포지토리 하나를 만들고 각자 폴더에 구현물을 올립니다.
- 정해진 이름 규칙: `01-주제`, `02-주제`처럼 순번과 주제를 함께 적습니다.
- 정해진 문서화 방식: 각자 폴더의 README에 프로젝트를 설명하고, `docs/`에 트러블슈팅을 기록합니다.
- 정해진 트러블슈팅 파일명: `YYYY-MM-DD-문제-요약.md` 형식으로, 기록한 날짜와 영문 소문자·하이픈으로 된 문제 요약을 사용합니다.

- 개인 폴더의 세부 구성은 어떻게 할까요?
- 브랜치와 PR을 사용할까요? 사용한다면 언제 올릴까요?
- 실행 방법과 의존성은 어디에 기록할까요?

### 6. 발표와 피드백

- 각자 어떤 내용과 분량으로 발표할까요?
- 결과물 시연, 코드 설명, 어려웠던 점 중 무엇을 공유할까요?
- 피드백은 어떤 방식으로 주고받을까요?

### 7. 첫 프로젝트 후보: 미래 자산 계산기

> 아래는 회의용 제안입니다. 주제, 기능, 계산 기준과 일정은 회의에서 결정합니다.

**목표:** 월급과 소비·저축 계획을 직접 입력하고, 매월 남는 돈과 일정 기간 뒤의 예상 자산을 터미널에서 확인합니다.

**사용 흐름 예시:** 현재 자산 입력 → 수입·지출·저축 계획 등록 → 기간 선택 → 월 잔액과 미래 자산 확인 → 계획을 수정해 다시 계산.

#### 공통 요구사항 후보

| 구분 | 제안 기능 |
| --- | --- |
| 수입 | 이름과 월 실수령액을 등록·조회·수정·삭제 |
| 소비 | 식비·주거비 등 항목별 월 지출을 등록·조회·수정·삭제 |
| 저축 | 예금·적금 계획의 이름, 원금 또는 월 납입액, 연 이율, 시작 시점과 기간을 등록·조회·수정·삭제 |
| 월 예산 | 월 수입, 소비, 저축 납입액과 남는 금액을 표시 |
| 자산 예측 | 현재 자산과 계획을 바탕으로 선택한 기간 뒤의 현금·저축 잔액과 총자산을 표시 |
| 저장 | 입력한 계획을 저장하고 프로그램을 다시 실행해도 불러오기 |
| 입력 검증 | 금액·기간·이율의 잘못된 입력을 안내하고 다시 입력받기 |
| 결과 설명 | 적용한 가정, 계산 기간, 이자·세금 반영 여부를 결과와 함께 표시 |

#### 계산 기준 논의

- **시작 잔액:** 현재 자산 중 현금과 기존 예금·적금을 어떻게 구분할까요? 같은 돈을 두 번 합산하지 않으려면?
- **월 흐름:** 수입, 소비, 적금 납입과 이자 계산 순서를 어떻게 정할까요? 수입과 지출은 매월 일정하다고 가정할까요?
- **예금·적금:** 예금은 일시 예치, 적금은 매월 납입으로 구분할까요? 이자 계산 방식과 월초·월말 납입 기준은?
- **만기 처리:** 만기 전 중도 해지 없이 잔액을 표시할까요? 만기 후 원금·이자를 현금으로 옮길까요?
- **현금 부족:** 수입보다 지출과 납입액이 크거나 잔액이 부족하면 경고, 납입 중단, 음수 잔액 중 어떻게 처리할까요?
- **세금과 이율:** 첫 버전은 고정 이율과 세전 예상액으로 통일하고 세후 계산은 선택 기능으로 둘까요? 적용하지 않는 조건은 어떻게 표시할까요?
- **기준 날짜와 반올림:** 시작 월, 계산 종료 시점과 원 단위 반올림 규칙은 어떻게 맞출까요?
- **검증:** 같은 입력을 각자 프로그램에 넣었을 때 같은 결과가 나오는 공통 예제를 정할까요?

#### 범위와 일정 논의

- **데이터:** 첫 버전은 상품명과 이율을 직접 입력하고, 공개 데이터 연동은 선택 기능으로 둘까요?
- **저장 방식:** JSON과 SQLite 등은 각자 선택할까요?
- **확장 후보:** 목표 자산 달성 시점, 월급 인상, 물가 상승, 여러 계획 비교 중 무엇을 선택 기능으로 둘까요?
- **기간:** 2주를 제안합니다. 중간 점검일과 발표일은 언제로 할까요?
- **레포 이름:** `01-future-asset-calculator`를 사용할까요?
- **개인정보:** 공개 레포에 실제 급여·자산 정보를 올리지 않도록 예시 데이터로 발표하고, 개인 입력 파일은 어떻게 관리할까요?
